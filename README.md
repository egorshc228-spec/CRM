# ADrenaline CRM

Внутренняя CRM агентства: заявки и воронка, клиенты и услуги, задачи команды, деньги (абонплата, счета, комиссии партнёров, деление AI-направления). Работает как сайт и как мини-приложение внутри Telegram. Вход через Telegram, API для рекламного AI-агента, приём заявок с сайта.

**Пошаговый план запуска — в файле [`DEPLOY.md`](DEPLOY.md).**

**Стек:** Node.js 22.13+ и SQLite (встроенный `node:sqlite`) — работает на **Railway** как обычный сервис рядом с ботом, база в файле на Volume. Внешних зависимостей нет. Тот же код по-прежнему разворачивается и на Cloudflare Pages + D1 (раздел «Альтернатива: Cloudflare»).

```
server/            сервер для Railway: интерфейс + API, база SQLite, резервные копии
public/            интерфейс (index.html, app.js, styles.css)
functions/api/     единая точка входа API: /api/* (общая для Railway и Cloudflare)
lib/               логика: auth, http, db, telegram, routes/*
migrations/        схема базы (на Railway применяется сама при запуске)
tools/             перенос задач со старой доски
test/              тесты: подписи Telegram, часовой пояс, база SQLite, API
Dockerfile, railway.json   сборка и запуск на Railway
wrangler.toml      настройки для Cloudflare (на Railway не используется)
```

## Последнее обновление — 0.3.0 (01.11.2026)

**CRM переведена на Railway.**
- Свой сервер на Node.js (`server/index.mjs`): отдаёт интерфейс и API. Логика CRM не менялась — тот же код, что на Cloudflare.
- База — SQLite-файл `crm.sqlite` на Volume (`DATA_DIR=/srv/data`). Прослойка с интерфейсом D1 (`server/sqlite-d1.mjs`), внешние ключи включены, как в D1.
- Таблицы создаются и обновляются **сами** при запуске (файлы из `migrations/`, каждый один раз). В консоль базы ничего вставлять не нужно.
- Все настройки — в Railway Variables, `wrangler.toml` на Railway не нужен.
- Резервная копия базы раз в сутки файлом в Telegram (после 3:00 по Киеву), включается `BACKUP_TG_CHAT_ID`.
- Проверка `/healthz` для Railway, корректное завершение при деплое, заголовки безопасности как на Cloudflare.
- `DEV_MODE` на Railway игнорируется, даже если задан по ошибке.
- Предупреждения в логах, если не задан `DATA_DIR` (база пропадёт при деплое) или переменные для входа.

Тесты: подписи Telegram — 10, часовой пояс — 3, база SQLite — 11, API — 51 (против сервера Railway-версии).

## Обновление 0.2.0 (01.11.2026)

**CRM как мини-приложение Telegram.** Открывается внутри Telegram по ссылке `t.me/<бот>/<приложение>` или кнопкой у бота, без браузера.
- Вход автоматический: сервер проверяет подпись данных, которые передаёт Telegram (`POST /api/auth/webapp`). Неприглашённому показывается его Telegram ID.
- Сессия внутри Telegram передаётся в заголовке `X-Session`: в веб-версии Telegram приложение открыто во фрейме, где cookie сторонних сайтов блокируются. В браузере всё по-прежнему через cookie.
- Ссылки в уведомлениях открывают мини-приложение сразу на нужной сделке, клиенте или задачах (`?startapp=deals_12`), если задан `TG_APP_SHORTNAME`. Без него ведут на сайт.
- Системная кнопка «Назад» Telegram ведёт из карточки в её раздел. «Выйти» закрывает приложение.
- Цвета шапки под CRM, отступы под системные панели Telegram.
- Заголовок `X-Frame-Options: DENY` заменён на `frame-ancestors` с разрешением только для `web.telegram.org`.
- Из миграции убрана строка `PRAGMA foreign_keys = ON`: в D1 проверка связей включена всегда, а строка может мешать при вставке в Console.

Тесты: подписи Telegram (виджет и мини-приложение) — 10 проверок, часовой пояс, API — 51 проверка.

## Обновление 0.1.1 (01.11.2026)

Исправлены ошибки, из-за которых могли пропасть или исказиться деньги:

1. **Удаление клиента или услуги со счетами запрещено.** Раньше вместе с клиентом удалялись его счета, и «Получено за месяц» уменьшалось. Теперь CRM отвечает «переведите клиента в статус «Ушёл»» (для услуги — «Завершена»). Клиента без счетов удалить можно, как раньше.
2. **Этап «Оплата» — только через кнопку «Оплатили».** Раньше через API можно было перевести сделку в «Оплату» без клиента, услуги и счёта. Новую сделку тоже нельзя создать сразу оплаченной.
3. **Проценты партнёра проверяются (0–100).** Раньше можно было сохранить, например, 500%. Все проверки в «Оплатили» идут до записи в базу, поэтому ошибка не оставляет лишнего клиента.
4. **Даты по Киеву.** «Сегодня», просрочки, даты оплат и время в ленте раньше считались по Гринвичу и ночью отставали на день.
5. **Счёт с выплаченной партнёру комиссией защищён.** С него нельзя снять оплату, поменять сумму или удалить его: иначе выплата пропадала из отчёта.
6. **Ошибки в окне «Подтвердите» показываются.** Раньше, если удаление не удавалось, интерфейс молчал.

Тесты: `npm test` (подпись Telegram, часовой пояс, 45 проверок API). Миграция базы не нужна.

Проверить старые данные (выполнить в Console базы D1) — сделки в «Оплате» без клиента, появившиеся из-за ошибки 2:
```sql
SELECT id, title, closed_at FROM deals WHERE stage = 'won' AND client_id IS NULL;
```
Если такие есть: откройте сделку и нажмите «Создать клиента ✓» — создадутся клиент, услуга и счёт за запуск.

## Что умеет

| Раздел | Что внутри |
|---|---|
| Сводка | мои задачи на неделю, новые заявки, «напомнить клиенту» (следующий шаг по сделке), оплаты на неделю, MRR, последние события |
| Воронка | Новая → На связи → Разбор → КП, перетаскивание карточек, «Оплатили» (создаёт клиента, услугу и счёт за запуск), «Отказ» с причиной, поиск, архив выигранных и отказов |
| Клиенты | услуги с абонплатой, рекламным бюджетом и ID кабинета, счета, задачи, лента заметок и звонков (сюда же пишет агент), контакты |
| Задачи | фильтр по человеку, группы «Просрочено / Сегодня / На неделе / Позже», уведомление исполнителю в Telegram |
| Деньги | MRR по направлениям, получено за месяц, долги и просрочка, «Выставить абонплату за месяц» (без дублей), комиссии партнёрам (20% запуска + 10% абонплаты 12 мес — настраивается в услуге), деление AI-направления поровну между участниками, график поступлений |
| Команда | доступы по Telegram ID, роли, кто получает долю AI, курс USD/UAH |

Роли: **владелец** — всё; **команда** — всё, кроме управления людьми, курсом и удаления; **AI-агент** — только чтение клиентов/сделок/задач, заметки и задачи.

## Развёртывание на Railway

Пошагово — в [`DEPLOY.md`](DEPLOY.md): бот в BotFather → репозиторий GitHub → сервис и Volume в Railway → домен → мини-приложение → команда.

Переменные Railway (Variables):

| Переменная | Что это |
|---|---|
| `DATA_DIR` | `/srv/data` — путь Volume, где лежит база |
| `TG_BOT_TOKEN` | токен бота CRM (секрет) |
| `TG_BOT_USERNAME` | логин бота без @ |
| `OWNER_TG_ID` | Telegram ID владельца — он станет владельцем при первом входе |
| `TG_NOTIFY_CHAT_ID` | ID группы команды для уведомлений (начинается с `-100`) |
| `CRM_URL` | `https://crm.adrenalinegrowth.com` |
| `TG_APP_SHORTNAME` | короткое имя мини-приложения из `/newapp` (например `crm`), пусто — ссылки ведут на сайт |
| `SESSION_SECRET` | случайная строка 32+ символов (секрет) |
| `AGENT_API_KEY` | ключ для AI-агента (секрет) |
| `INTAKE_KEY` | ключ для приёма заявок с сайта и из ботов (секрет) |
| `BACKUP_TG_CHAT_ID` | куда слать ежедневную копию базы (обычно ID владельца); пусто — копий нет |
| `BACKUP_HOUR` | час отправки копии по Киеву, по умолчанию 3 |

`PORT` Railway задаёт сам. `DEV_MODE` не задавать.

### Перенос задач со старой доски
```
node tools/import-tasks.mjs https://crm.adrenalinegrowth.com <AGENT_API_KEY>
```
Переносит 50 задач из `tools/team-board-tasks.json` (выгрузка доски команды) с исполнителями по имени. Запускать один раз, после того как вся команда добавлена. Уведомления при переносе не отправляются.


## Альтернатива: Cloudflare Pages + D1

Тот же код работает на Cloudflare без сервера (бесплатно на нашем объёме). Кратко:

Секреты вводит только Даниил — в Cloudflare и BotFather. В репозиторий и в чаты их не кладём.

#### 1. Бот для входа
1. В @BotFather: `/newbot` → например `adrenaline_crm_bot`. Сохраните токен — это `TG_BOT_TOKEN`.
2. Там же: `/setdomain` → выберите бота → домен CRM, например `crm.adrenalinegrowth.com`. Без этого кнопка «Войти через Telegram» не появится.
3. Свой Telegram ID можно узнать у @userinfobot — это `OWNER_TG_ID`.
4. Для уведомлений о заявках: добавьте бота в группу команды, напишите в ней сообщение и откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — `chat.id` группы (начинается с `-100`) это `TG_NOTIFY_CHAT_ID`.

#### 2. База D1
Cloudflare → Workers & Pages → D1 SQL Database → **Create** → имя `adrenaline-crm`.
Скопируйте **Database ID** и вставьте его в `wrangler.toml` вместо нулей (это не секрет).
Откройте базу → **Console** → вставьте всё содержимое `migrations/0001_init.sql` → **Execute**.

#### 3. Репозиторий и Pages
1. Создайте приватный репозиторий `adrenaline-crm` на GitHub и загрузите туда файлы проекта (без `node_modules`, `.wrangler`, `.dev.vars`).
2. В `wrangler.toml` заполните `[vars]`: `TG_BOT_USERNAME` (без @), `OWNER_TG_ID`, `CRM_URL` (`https://crm.adrenalinegrowth.com`), `TG_NOTIFY_CHAT_ID`.
3. Cloudflare → Workers & Pages → Create → Pages → **Connect to Git** → репозиторий. Build command — пусто, Build output directory — `public`. Deploy.
4. Pages → проект → Settings → **Variables and Secrets** → добавьте как *Secret* (Production):
   - `TG_BOT_TOKEN` — токен бота
   - `SESSION_SECRET` — случайная строка 32+ символов
   - `AGENT_API_KEY` — случайная строка для AI-агента
   - `INTAKE_KEY` — случайная строка для сайта

   Случайную строку можно получить командой `openssl rand -hex 32` или в любом генераторе паролей.
5. Pages → Custom domains → `crm.adrenalinegrowth.com`. Затем Deployments → **Retry deployment**, чтобы подхватились секреты.

Важно: `DEV_MODE` на продакшене **не задавать** — он включает вход без Telegram.

#### 4. Первый вход и команда
1. Откройте CRM и войдите через Telegram — владелец создаётся автоматически по `OWNER_TG_ID`.
2. Єгор и Даня открывают CRM и жмут «Войти» — им покажется их Telegram ID. Добавьте их в «Команду» и отметьте «Доля AI».
3. Каждый один раз жмёт **Start** у бота — иначе бот не сможет писать им о новых задачах.

#### 5. Заявки с сайта
В проекте сайта (`adrenaline-site`) обновлён `functions/api/lead.js` — он дополнительно шлёт копию заявки в CRM. В настройках Pages сайта добавьте:
- `CRM_INTAKE_URL` = `https://crm.adrenalinegrowth.com/api/intake`
- `CRM_INTAKE_KEY` (Secret) = тот же `INTAKE_KEY`

Заявка падает в «Новая», источник ставится автоматически (с gclid или utm cpc — «Реклама», иначе «Сайт»), услуга угадывается по полю «Що цікавить», UTM и ключ сохраняются. Повтор с того же контакта за 24 часа дописывается в ту же сделку. Если CRM недоступна, форма работает как раньше.

## API для AI-агента

Все запросы с заголовком `Authorization: Bearer <AGENT_API_KEY>`.

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/agent/summary` | все активные клиенты: услуги, абонплата, рекламный бюджет, ID кабинета, открытые задачи, неоплаченные счета, 3 последние заметки |
| GET | `/api/clients?status=active` | список клиентов |
| GET | `/api/clients/:id` | карточка: услуги, счета, задачи, лента, сделки |
| POST | `/api/clients/:id/notes` | `{ "text": "CPL вырос на 30%, снизил ставки в группе X" }` — заметка в ленту клиента (с пометкой 🤖) |
| GET | `/api/tasks?assignee=all&status=open&client_id=5` | задачи |
| POST | `/api/tasks` | `{ "title": "...", "client_id": 5, "assignee_id": 2, "due": "2026-11-01", "priority": 1, "silent": false }` |
| PATCH | `/api/tasks/:id` | `{ "status": "done" }` |
| GET | `/api/deals?stage=open` | воронка |
| GET | `/api/users` | люди (для `assignee_id`) |

Счета, деньги и управление командой агенту закрыты (403).

Для MCP-сервера агента достаточно двух инструментов: `get_client_context` → `GET /api/clients/:id` (или `/api/agent/summary`), `save_note` → `POST /api/clients/:id/notes`. Сопоставление клиентов агента и CRM — по названию или по ID кабинета в услуге.

## Приём заявок из других источников

`POST /api/intake`, заголовок `X-Intake-Key`, тело как у формы сайта:
```json
{ "name": "Ирина", "contact": "+380501112233", "niche": "Стоматология, Одесса", "service": "AI-адміністратор",
  "budget": "$500", "pain": "...", "source": "telegram", "attribution": { "utm_source": "...", "gclid": "..." } }
```
Так же можно подключить бота продаж или n8n.

## Локальная разработка

Нужен Node.js 22.13+. Установка пакетов не требуется (кроме варианта для Cloudflare).

```
cp .dev.vars.example .dev.vars
npm run dev          # http://localhost:8788 — вход «dev» без Telegram, база в ./data
node test/demo.mjs   # вымышленные демо-данные
npm test             # подписи, часовой пояс, база, smoke-тест API (сервер должен быть запущен)
```

Новая миграция — файл `migrations/0002_*.sql`: на Railway применится сама при следующем запуске (для Cloudflare — `npm run db:remote:cf` или SQL в Console базы).

## Безопасность

- Вход только для Telegram ID из таблицы `users`; подпись Telegram проверяется по токену бота, вход старше суток отклоняется.
- Сессия — подписанная HttpOnly-cookie на 30 дней; изменяющие запросы из браузера принимаются только со своего домена.
- Ключи агента и сайта сравниваются за постоянное время; у агента — белый список методов.
- Сайт закрыт от индексации (`noindex`).
- Встраивать CRM во фрейм можно только самой CRM и веб-версии Telegram (`frame-ancestors`).
- Вход из мини-приложения проверяется по подписи Telegram (ключ из токена бота), данные старше суток отклоняются.
